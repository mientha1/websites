# pic à bec — PrestaShop implementation map

Target: `themes/hummingbird-child` (child of official Hummingbird 2.x, Bootstrap 5.3.3, PS 9.x).
Single override point: **`themes/hummingbird-child/assets/css/custom.css`** (core registers it at priority 1000, after `theme.css`) and **`themes/hummingbird-child/assets/js/custom.js`** (priority 1000, bottom). Parent theme rules live inside `@layer` (`vendors, bs-base, bs-components, bs-custom-components, ps-base, ps-components, ps-pages, ps-modules, utilities`), so **unlayered rules in `custom.css` beat them regardless of specificity — you almost never need `!important` against the parent.** You do need it against the *existing* `custom.css`, which is the real problem (see Risks).

## 1. Summary

Roughly **85 % of the visual transformation is pure `custom.css`**: tokens, the whole type system (self-hosted `@font-face` + killing the global uppercase), colour, spacing, buttons, forms, header bar, product card geometry, 4-column grid, filter drawer, cart, checkout step chrome, footer, focus states. The prototype's class names deliberately match what already exists (`.product-miniature__*`, `.pic-filter-panel__*`, `.cart-grid__*`, `.checkout-steps__*`, `.footer-pic__*`, `.header-pic__*`), so most of `assets/css/styles.css` ports across with a handful of wrapper renames. The exceptions needing Smarty edits are few and each is small: **horizontal desktop nav**, a **second `<img>` in the miniature**, the **mosaic gallery**, the **sticky mobile buy bar**, **quick-add size chips**, the **free-shipping meter**, the **newsletter block** (module install), and the **designed empty / out-of-stock states**. Nothing requires touching core or a module's PHP.

## 5. Do this first

1. **Clean-up pass on `custom.css`**: delete the global uppercase rules, `a:focus{outline:none}`, the duplicate `a{}` block, the redefined `.pb-*`/`.mt-*`/`.mb-*` utilities, the stray `max-width:764px` and the 768px `min`/`max` overlap. Nothing else works predictably until this is done.
2. **Fonts**: drop the woff2 files into `assets/fonts/`, paste the `@font-face` block at the top of `custom.css`, alias `--font-family-mulish`.
3. **Tokens**: paste the `:root` block including the legacy aliases and the corrected `--bs-*` overrides. At this point the site is already recognisably the redesign.
4. **Type scale**: `body`, headings, `.page-title-section`, `.eyebrow`, `.rte`, `.link-underline`, plus `:focus-visible`.
5. **Buttons + forms + accordion** — one pass, since these appear on every page.
6. **Header + announcement bar + footer** — the frame around everything.
7. **Product card + `.products` grid columns** (CSS only), then the miniature `.tpl` for the alt image, out-of-stock modifier and quick-add.
8. **Category page**: header, sticky `#js-product-list-top` toolbar, filter drawer, active chips, pagination, empty state.
9. **Product page**: prices, variants, qty/ATC, availability, accordion — then the gallery `.tpl` and the sticky buy bar.
10. **Cart** (lines, summary, voucher) then the free-shipping meter `.tpl`.
11. **Checkout**: steps chrome, delivery/payment option rows, mobile summary, then `checkout-step.tpl`.
12. **Nav + newsletter last**: the desktop `.pic-menu` template work and the `ps_emailsubscription` install — both are additive and shouldn't block the rest.

## 6. Risks and gotchas

- **`!important` arms race.** The parent is layered, so `custom.css` wins for free — but the *existing* `custom.css` uses `!important` liberally (uppercase, `--bs-primary-rgb`, spacing utilities). Since new rules live in the same file, cascade order decides: put the new system **above** legacy blocks and delete what it replaces, rather than appending `!important` and doubling the file.
- **Redefined Bootstrap utilities.** `.pb-1`–`.pb-5`, `.mt-1`–`.mt-5`, `.mb-1`–`.mb-6` are overridden site-wide. Theme and module templates use `mb-3`, `mt-3`, `mt-4`, `py-3`, `gx-2 gx-md-4` etc. — every one of them is currently mis-spaced. Restore Bootstrap's values and express layout spacing through the new component rules and `--space-*`.
- **Module markup drift.** `ps_facetedsearch` wrappers (`#offcanvas-faceted`, `#search_filters_wrapper`, `#search_filter_controls`), `blockreassurance`, `ps_socialfollow` and payment forms are module-owned and change on update. Style them defensively (attribute/BEM-root selectors, no `nth-child` chains) and never rename `js-*`, `data-ps-ref`, `data-ps-action` hooks.
- **Breakpoint collision.** `min-width:768px` and `max-width:768px` both fire at exactly 768px, and there's a stray `764px`. Also note this theme's Bootstrap map is non-standard: `xxs:0, xs:360px, sm:576px, md:768px, lg:992px, xl:1200px, xxl:1400px` — `col-xs-*`/`d-xs-*` exist and mean 360px. Pick one convention: `max-width: 767.98px` for down-queries, and use the prototype's own breakpoints (700/900/1000/1080/1100) consistently.
- **Polish text length + i18n.** Uppercase + `letter-spacing: .11em` on Polish labels ("Dodaj do koszyka", "Kontynuuj zakupy", "Chwilowo niedostępny", "Przejdź do płatności") overflows fixed-height buttons and the nav. Give `.btn` a `min-height` with wrapping allowed rather than a fixed height, test the filter drawer footer and `.checkout-steps` labels, and keep the latin-ext font files. If RTL is ever enabled, the theme ships `theme_rtl` and `.rtl-flip` conventions — use logical properties (`padding-inline`, `margin-inline`, `inset-inline`) as the prototype does.
- **Image aspect ratios.** `large_default` / `product_main` / `small_default` are near-square by default; the redesign uses 4:5 cards and 3:4/4:4.4 gallery cells. Two options: (a) keep the image types and rely on `aspect-ratio` + `object-fit: cover` with `object-position: center 42%` (no regeneration, but heads/feet can be cropped — check hats, belts and socks specifically); or (b) add a proper 4:5 image type in **Design → Image Settings** and regenerate thumbnails (long job on a live catalogue, and template `srcset`/`sizes` reference the existing type names, so the `.tpl` must be edited too). Recommendation: ship (a) first, evaluate crops per category, and only regenerate if the crop is unacceptable on flat-lay products. Keep `.product-miniature__image-container` as the aspect-ratio owner so the grid never reflows while images load.
